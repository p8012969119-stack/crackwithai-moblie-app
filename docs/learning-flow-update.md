4. **Locked cards removed.** Course Details now renders the course title, actual module/lesson counts and the existing module roadmap. The normal screen contains no Final Assessment card, Certificate Locked card, certificate preview or placeholder space. Modules start collapsed. The only additional success section appears after the backend confirms course completion.

5. **Four-module flow.** All four published modules come from the backend. Titles, descriptions, lessons, progress and locks remain data-driven. Start/Continue opens the existing Lesson route, retaining topic navigation, practice, lesson quizzes, previous/next behavior and sequential unlocks. Quiz results distinguish module completion and offer the appropriate next lesson/module action. All 15 seeded courses were verified to have four modules and twelve lessons. Completion rejects curricula that do not have exactly four modules; the UI does not fabricate or silently discard curriculum modules.

6. **First ten / Show More.** The list initially slices the real filtered catalog to ten entries. Show More displays all remaining entries and becomes Show Less. Collapse returns to ten and scrolls to the top. The control is absent when there are ten or fewer entries. Existing stable IDs prevent duplicate rows.

7. **Search across the complete catalog.** Title, description and short description are searched before any display limit is applied. Active search displays all matching results, including courses outside the first ten. Both All Courses and My Learning use this behavior; My Learning retains the enrollment filter. No results and no enrolled courses have separate empty states. The simulator confirmed that Claude, outside the initial ten, was searchable in both tabs.

8. **Progress causes.** Existing code mixed an average of course percentages with lesson totals, used fallback lesson counts, could include stale/foreign/duplicate saved lesson IDs, and could interpret 100% lesson progress as a completed course. Home/Profile also used inconsistent course selection and fabricated Profile values, including 45%, eighteen lessons and an invented current course/time remaining. Mount/focus fetching could duplicate requests or display stale results.

9. **Progress correction.** A shared backend projection intersects saved completions with each course's current published lesson IDs. It computes module completion from required lessons and exposes canonical counts to course details, My Learning and dashboard consumers. Overall progress is weighted lesson progress across enrolled published courses: completed lessons divided by total lessons, rounded to a percentage. Per-course and per-module percentages describe their own respective lesson sets. Completed-course counts use confirmed completion, not percentage alone. Empty totals yield zero; UI percentages are bounded. Home uses the dashboard's real course data and Profile uses the same dashboard totals. Focus refreshes, cancellation and loading/error handling prevent outdated requests from overwriting current data. Profile's fabricated current-course/time fallback was removed.

10. **Course completion.** All four modules and every required lesson must be complete under existing backend lesson/quiz rules. The existing product also requires its final course quiz to pass. That rule was preserved: after learning is complete, an actionable final-quiz footer is available; there is no locked final-assessment card during normal learning. A successful backend completion operation persists completion only after those checks. Simply opening a course/module, completing one lesson/module, reaching a frontend percentage or failing an API request cannot complete the course.

11. **Certificate unlocking.** The backend rechecks curriculum completion and the existing passed-assessment requirements before issuing a certificate. The frontend requests the existing issuance API, requires an active certificate response and opens the existing Certificates route with the returned ID. A failed request shows a retryable error and does not navigate to an invented certificate. Course Completed and the certificate action depend on confirmed backend completion.

12. **Violet action.** Course Details and successful quiz results use the existing ActionButton's purple variant for View Certificate. The certificate screen/modal uses purple View/Download actions with white text and rounded corners. The pre-completion screen has no grey locked certificate button or duplicate preview.

13. **Certificate design and data.** The existing screen/modal/canvas was reused. The mobile canvas and landscape PDF adapt the screenshot's double frame, corner ribbons, gold-edged brand medallion, serif certificate title/recipient, date and signature hierarchy to violet branding. This is a responsive adaptation, not a pixel-identical copy of the green desktop screenshot. Real recipient/course/date/certificate ID/score/verification values come from the certificate response and authenticated user; missing data is omitted or explicitly marked unavailable. No date, score, completion or credential ID is invented. The screenshot's QR feature was not recreated. A real certificate generated by the isolated backend test was rendered to a one-page PDF and visually checked for clipping and hierarchy.
